# AI Mastery Atlas V19 — Protected Progress Imports

This candidate continues published V18 `1bc64083b831831d6165a673c45c363ff3726e81`. The change addresses a reproduced core progress-import race: a backup finishing after newer Studio edits could clear the autosave queue and replace visible fields before those edits reached a recoverable checkpoint. A second selected file could also be overwritten by an older read finishing later. The preserved pre-fix reproducer uses the exact old handler and real validators/writer; it is source-driven evidence, separate from mounted Home and real-browser checks.

Core progress imports now have a selection token, immediate edit invalidation, a rendered revision, writer/head identity checks, live private-URL checks and a mounted lifetime. Child core edits, new or empty selections, native picker cancellation, explicit cancellation, privacy navigation and unmount retire an older read. The importer checks again before private storage access, confirmation and application, including an edit made inside the confirmation boundary. A same-value edit refreshes the rendered revision rather than leaving visible controls permanently stale.

Before an approved replacement, the existing writer preserves the complete queued current head through its existing protected checkpoint and original-recovery archive. This includes work already queued before file selection. Preservation must succeed and be checked; quota, conflict, damaged recovery indices or the five-original limit refuse replacement without clearing queued fields. The incoming canonical copy must then save successfully before the visible learner fields change. Failed incoming proposals and the preceding current head remain separately recoverable. Derived recovery exports include the exact current in-memory queued JSON; no stored schema, key or namespace changed. Exact legacy bytes remain separate from current checkpoints. A successful checked recovery import enables editing again; unsupported imports continue to be refused.

Home synchronizes its existing Share-safe view on `popstate` and `hashchange`. Public projections mask core preferences, track evidence, private source notes and progress while preserving the actual state in its existing hooks. Shared projections never enter the autosave queue. Core imports, reset, raw recovery and progress exports check the current URL at action time, before React has had time to update. No global history method is patched. A direct URL mutation without a navigation event cannot update React immediately; current-URL action guards still refuse private actions, and an observed shared URL retires pending core imports.

Existing child workspaces receive the current shared view and render public notices without clearing their private drafts. The task desk preserves same-unit unsubmitted fields across paused and shared transitions, including a refused draft save, rather than reloading an older stored draft over them. The Subject Study Lab retains its unexported prompt. Academy notes/checks, uncontrolled Evaluation form values, Operator Studio fields and local benchmark drafts survive a private → shared → private cycle. Private exports and captured callbacks are guarded in their owning workspaces. These are preservation and privacy boundaries, not evidence of academic completion.

The Paper Analysis Studio retains its V18 implementation: strict `atlas-paper-audit-v1`, 2 MB worksheet bound, 100 rows, five retained copies, selected-only restore, literal recovery, unknown-field refusal and the same-value retained-selection regression. Its original component, schema and academic isolation remain unchanged. No new store, dependency, PHP, model call, account action, upload, cross-site transfer, corpus, answer key or automatic review promotion is added.

Queued work still depends on the tab until a checked save or verified export exists. A browser unload warning is requested when an unsaved queue differs from the protected current head; browsers control whether that warning appears. Download actions request a file and do not certify that a backup was saved or opened. Tests use synthetic data; historical-format and failure fixtures do not prove every production record is valid. Root-owned full type/lint/build, complete TAP and real-browser reports must report their own passes, failures and skips. The ten-check browser helper is not counted as executed before its final build and reports exist. Publication, access-policy readback and rollback packaging remain separate gates.
