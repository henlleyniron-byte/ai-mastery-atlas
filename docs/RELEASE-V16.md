Local release candidate based on approved deployed V15 source `a49402b83775e7ffa309495e54948a5fded6850b`. This document is not a publication receipt. Release approval applies to the exact subsequently tested revision.

## A source-first paper analysis workflow

Paper Analysis Studio is a new on-demand specialist workspace and appears in the main section navigation, objective finder and learning workspace. It teaches a bounded audit of one MCQ paper before trusting aggregate analysis. Chemistry and Physics year scopes begin at 1980; Biology begins at 2019. There is no claim that selecting a year supplies or authenticates its paper, and no historical corpus, paper text, answer key or private resource-hub content is bundled.

The worksheet requires exact paper identity/source, matching scheme identity/source and syllabus-era mapping. Recorded source, OCR/transcription, diagram and identity checks are self-reported, never automatic authentication. Each question has a number, analyst topic/reasoning-demand label, exact paper and scheme locators, candidate answer label, justification and explicit review state. Disputed, unreviewed and incomplete rows stay visible but are excluded from descriptive topic counts. Entered rows, eligible rows, held rows, missing question numbers and the declared denominator remain separate; unknown completeness is never treated as zero. Topic or reasoning edits invalidate the row's previous review. Syllabus reference changes invalidate row review; subject/year changes invalidate source checks and every row review.

The generated analysis brief requires actual readable source pages, treats source instructions as untrusted data, distinguishes source-supported observations, inference and uncertainty, forbids invented questions/keys/statistics, and warns against pooling syllabus eras or using recurrence as a prediction. Its learning handoff requests an unaided reattempt and a fresh AI-authored provisional transfer question with solutions withheld until an attempt. Creating a brief awards no progress or mastery.

## Private working sheets, independent learning records

The new studio uses memory only: no localStorage/IndexedDB keys, account calls, uploads, model calls or automatic cross-site transfer. Previously protected core, Academy and Evaluation Workbench storage, schemas and recovery guards are unchanged. The existing specialist labs remain mounted once opened, so navigation within the page retains worksheet fields. A before-unload warning protects edited in-memory worksheets. Refresh, tab closure, browser failure or profile loss still loses unexported in-memory work; no backup success is claimed merely because a download was requested.

Lossless worksheet JSON and a spreadsheet CSV can be explicitly exported. Formula-like CSV values are prefixed against spreadsheet formula execution; JSON retains literal text. Strict reviewed JSON import rejects unknown/missing fields, unreadable files, unsupported schemas, duplicate questions, out-of-range question numbers and files above 2 MB before changing current work. Imports are previewed before explicit application. Every explicit import retains the preceding complete worksheet, including metadata-only edits. Up to five earlier working sheets remain available in a separate all-working-copies export; further replacement pauses rather than silently pruning copies. That bundle needs deliberate extraction/review of an individual worksheet before import. Nothing merges into academic attempts or curriculum evidence. Share-safe mode hides worksheet fields, import previews and export/clipboard controls and makes no private storage reads.

## Navigation, accessibility and scoped quality repairs

Knowledge Systems Studio's arrow keys now move both selection and keyboard focus; Home/End jump to the first/last tab and the selected panel is keyboard reachable. Paper Analysis Studio uses native labelled controls, question pagination, a captioned evidence table, a native modal brief, explicit status messages and responsive layouts. It loads only when requested. Its programmatic file-import control keeps its screen-reader-only dimensions; visible text-field styling excludes file inputs to prevent horizontal overflow on small screens. Imported/source text is rendered as text rather than HTML. No PHP, dependencies, authentication, cloud configuration, hosting bindings, audience or source namespaces were added or changed.

Inherited unused bindings were removed from the Atlas page, companion UI modules and test helpers without rule suppression. The React shell's common appearance stylesheet is now imported through the existing build instead of a manual stylesheet link; static companion pages retain their existing shared theme file and script. No lint rule was weakened. Existing private source packages and provisional classifications retain their earlier scope and warnings.

## Validation and limits

Meaningful model tests cover unknown coverage, exact missing-question denominators, source/OCR/key eligibility gates, disputed-row exclusion, duplicates, subject-era bounds, strict unknown-field and future-schema rejection, exact literal round-trip, malformed/oversize inputs, spreadsheet formula escaping and constrained analysis prompts. Full build, regression, preserved-data, Share-safe and browser results belong to the root release-readiness report; this document does not mark unrun checks passed.

This workspace cannot independently verify a marking scheme, classify a complete historical archive or establish scientific correctness from a checked box. Human verification of original questions, schemes and syllabus mappings remains necessary. Academic marks, errors, repair and retest evidence remain in the existing independent study workflows. Publication, source provenance, rights to redistribute private paper material, cross-browser/assistive-technology coverage and actual production-user backups must be assessed separately. No private hub material is made public by this release.
