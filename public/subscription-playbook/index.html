Start

01 · Start here: a useful result in 15 minutes

Your objective is better independent performance and less administrative effort. Reading more AI news, spending longer chatting, or exhausting a quota is not the objective. This playbook is an optional operating guide alongside the Atlas curriculum; it adds no compulsory curriculum hours and awards no mastery automatically.

First session: choose one already-attempted question. Keep the question, your original answer, and a trusted scheme or resource-book passage together. Use ONE assistant to diagnose the smallest error. Check its explanation against your source. Close the answer and solve the question again. Record the actual result in your existing evidence system. Stop once the repair is tested.

An app is where you work: ChatGPT, Claude or Gemini. A model is the engine selected inside it. A subscription buys a bundle of access and limits. A project is a reusable workspace for related instructions and source files. A connector allows supported access to another service. An API is a separate way for software to call a model; it can create separate charges. A website guide teaches these tools; its search box does not itself run ChatGPT, Claude or Gemini.

Choose a role rather than a winner. My suggested starting arrangement is ChatGPT for the main study conversation and supported tool actions, Claude for an occasional independent critique or bounded document/code task, and Gemini Notebook/NotebookLM for comparing a selected source collection. These are workflow recommendations, not measured universal model rankings. One capable free assistant plus official sources can perform much of the same study loop.

Finish test: without this page, explain which tool you chose, what it helped with, what you checked yourself and whether you can now solve the question independently.

Value

02 · Protect essentials and examine overlap

Food, prescribed medication, basic household needs and necessary learning access take precedence over discretionary subscriptions. If paying for AI currently prevents meeting those needs, reduce or pause the least useful paid service now; do not wait for a two-week experiment to establish that essentials matter. Do not ration medication to finance AI. If access to prescribed treatment is affected, contact your prescriber or pharmacist for help finding an affordable route; an AI assistant cannot replace treatment.

There is no obligation to keep all three plans. Past payments do not make future renewals worthwhile. A paid subscription is not a promise of marks, a university place, employment or an income stream. More expensive models cannot compensate for missing first attempts or unchecked marking.

Use the actual billed amount, taxes, currency conversion and renewal date from each account. Do not guess a Sri Lankan price from an American advertised price. Check whether a subscription is monthly, prepaid, a promotion or billed through an app store. Before changing a storage bundle, check current usage and the provider’s downgrade guidance. Cancel through the channel that actually bills you, retain confirmation and check the next renewal state. This guide never cancels accounts for you.

Ask of each service: What verified work did it uniquely help me finish this month? Could the same work be done adequately through another subscription, free access or my own method? How much correction and setup time did it add? If its unique benefit is small, pause its next renewal and keep your exports. Do not buy an annual plan solely for a discount while essentials or future use are uncertain.

The value worksheet below uses temporary numbers in this page only. It sends nothing to a server and saves nothing between visits. It estimates net time; it cannot prove causation, academic improvement or financial return.

Use AI Mastery Atlas when you need to learn a tool or process. Start with the beginner route, then use the relevant ChatGPT, Claude, Gemini or knowledge-systems lesson. The full curriculum is optional breadth. Do not complete every advanced track before starting useful study work.

Use Performance Powerhouse when you need to execute: choose a bounded question, use the timer, record real evidence, inspect repairs and return for a delayed check. Use Science Intelligence to navigate subject evidence. Physics, Chemistry and Biology labs help find question families and source-attributed mappings. Historical frequency describes past material; it does not establish the next paper’s content or justify skipping units.

Use Resource Desk to retrieve one resource for an exposed weakness. Use Private Study Library to search an imported study snapshot and inspect its version. That import is a snapshot, not live Drive access. It stays in its page/tab unless you explicitly choose browser saving. Different site origins have separate browser storage; importing at one origin does not automatically populate the other.

Use your existing Notion Paper Engine and Error Bank as the canonical account of actual academic attempts and verified errors. Google Calendar holds intended time. Drive holds source documents. Anki or RemNote holds selected retrieval items. xTiles can remain a weekly cockpit. Avoid copying the same daily result into every application: link to the authoritative record.

Some existing labs maintain independent local practice logs. They are not automatically merged into Notion. A navigation link is not a connector. A copied prompt is not an executed action. A timer session is not proof that a paper was marked. This playbook adds no competing attempt database.

ChatGPT

04 · ChatGPT Plus: set up your main workspace

Open the paid account you intend to use and confirm the plan in its account settings. If you use more than one account, verify which account owns the subscription, files and connections. A support request or usage screenshot from a different account cannot establish this account’s allowance.

Organise three subject workspaces or clearly separated conversations: A/L Biology, A/L Chemistry and A/L Physics. Add a compact instruction specifying Sri Lankan G.C.E. A/L, English medium, current syllabus, source hierarchy, hints before solutions and honest uncertainty. Add only useful authorised source files. Test a project’s retrieval with a question whose answer you know; do not assume every uploaded page was read.

The official documentation describes projects, files, search, images and plugins. Work can create artifacts and act through supported connected tools. Availability varies by account, platform, region and rollout. Confirm controls in your own interface. Use ordinary chat for a narrow explanation; use a tool-enabled work session for an actual spreadsheet, document or site change. Do not treat a product screenshot or API catalogue as proof of access to every model.

Use the lightest available model or mode that solves the job adequately. Escalate when it misses a real requirement, struggles with the reasoning or needs a specific tool. For a difficult numerical problem, request a clear derivation with assumptions, equations, units and checks. Longer output is not automatically better feedback.

Try a guided tutoring instruction: give one hint, ask one question, wait for my answer. A named study feature may be available in the app; the tutoring instruction also works in a normal conversation. For marking, upload the exact question, your untouched answer and the scheme. Ask for provisional point-by-point comparison, with unmatched or unreadable points held for teacher checking.

When using Drive, Notion or Calendar, state the exact target and permitted action. Inspect returned content before changes and verify the actual saved record afterwards. Grant the minimum useful access. If no connector can perform the action, retain a clearly labelled draft rather than claiming a write occurred.

Independent check: retrieve one known fact from a selected file, identify its location, and correct an intentionally wrong claim in the assistant’s response. You have learned the workflow when you can do this without copying the worked example.

Claude

05 · Claude Pro: critique, long documents and bounded builds

Claude Pro includes greater usage than Free and Claude Code access; API use through the Console is separately billed. Its official Pro help describes five-hour session limits plus a weekly limit across models. Message length, attached files, conversation length and feature/model choice affect usage. Inspect Settings > Usage rather than assuming a fixed number of messages.

Use a Project for a recurring task: add concise instructions and a small curated source collection. Start a new conversation inside it for a distinct question. Claude’s project guidance describes reusable knowledge and instructions. Test retrieval against a known passage; a large workspace is not proof that every source was consulted.

Your highest-value second opinion is a targeted critique: give the original question, source and your reasoning; ask Claude to find the first unsupported step. You need not supply another model’s conclusion initially. Verify the disputed point yourself. Use a second assistant only when there is a specific unresolved reason; agreement between models does not establish truth.

For documents and artifacts, define the audience, format and acceptance criteria. Request one deliverable, inspect the rendered result, ask for one consolidated revision and retain the export. Artifacts can be created and edited across supported Claude surfaces; sharing controls differ. Check who can open a published output before sharing private material.

Claude Code is a coding tool with file and command access. It is optional for an A/L student. Begin with a read-only explanation of a disposable project. Next request a small reversible edit, inspect the diff, run the relevant tests and understand recovery before a production change. Never paste secret keys, approve unexplained commands or assume signing into Code through API credentials uses the Pro allowance.

Extra usage or credits can create charges beyond the included plan. Keep them disabled unless you deliberately budget for them. When limits are reached, switch to your source and independent study, wait for the displayed reset or use an adequate free route. A quota limit is not a reason to upgrade automatically.

Start with a specific page, table or question. Long ongoing chats, large-file analysis and Deep Research consume more capacity than short queries. Start a fresh chat for a new topic and retain a compact handoff.

Use Gemini for a current, source-supported explanation, a bounded comparison or an available Google app workflow. In connected apps, verify the target file and the resulting saved state. A paid Google plan does not automatically mean this ChatGPT session can access every Google product, or that the three assistants share memory.

Search

07 · Search properly: from a question to an opened source

First classify the question. A stable concept usually needs your syllabus or resource book, not broad web research. A changing subscription feature needs dated official provider documentation. A private document needs Drive/library search with permission to read it. A research question with conflicting evidence may justify a deeper search.

Write a narrow query with the product, feature and account context. Example: Claude Pro weekly usage limits official. For an academic definition, search the exact resource-book section or scheme before a generic web answer. Search by file title in Drive, then open the correct version; a search snippet is not the full document.

Ask for official or primary sources first. Open the source, inspect its date and the passage supporting the claim. A page’s publication or modification date is different from the date of the event described. Ask the assistant to report conflicts and inaccessible sources. Do not invent a URL or accept one merely because it looks credible.

Use normal search for one changing fact. Use Deep Research only when you have a clear comparison, source set or contested question that warrants multi-step investigation. Before running it, specify the question, scope, relevant geography, date range, preferred source types and desired output. Review its plan when the tool offers one. Stop when enough reliable evidence answers the question.

For Sri Lankan A/L answers, distinguish syllabus scope, the relevant resource-book treatment, and the specific paper’s scheme. Teacher clarification can resolve ambiguity; extra university-level detail may be true yet irrelevant to the expected answer. Never award yourself official marks from a model alone.

Search success means finding the exact supporting passage and using it correctly. Saving dozens of links without opening them produces a reading queue, not verified knowledge.

Prompts

08 · Write one effective request and refine deliberately

A useful prompt gives six things: the task, context, source, constraints, output format and success check. Plain English is sufficient. You do not need elaborate roleplay or a perfect prompt before starting.

Example: I attempted this Chemistry question. Here are my answer and the scheme. Identify the first invalid step; keep feedback below 200 words, then give one changed practice question without its solution. Check units and conservation. This gives more useful guidance than explain all of equilibrium in maximum detail.

Ask the assistant to state missing input and assumptions. If an image is unclear, require it to quote what it can actually read before solving. Retype the relevant values, labels or equations if necessary. Do not let it silently repair an illegible question into a different one.

When a result fails, say which acceptance criterion failed and provide the evidence. Revise one dimension at a time. Avoid regenerating the entire output repeatedly. End with one consolidation: a final corrected result, sources, uncertainties and next independent action.

Give requests an appropriate length budget. A detailed explanation can be valuable when you lack a concept; a single wrong sign needs a focused correction. Use a compact context handoff for a new conversation: objective, verified facts, source versions, actions already completed, unresolved point and next action. Do not copy the entire history if a short handoff will do.

Finish test: give a new assistant enough context to continue correctly while leaving out private or irrelevant detail. If it asks sensible narrow questions rather than making assumptions, your handoff is working.

Study

09 · Biology: exact wording, essays and careful cards

Part I — MCQs: attempt the actual question without help. Record your option and confidence before marking. When wrong or guessed, identify whether the cause was missing knowledge, misunderstood wording, weak discrimination or retrieval failure. A model-generated answer key is provisional unless verified.

Part II — structured responses: compare each response to the relevant scheme and resource-book passage. Ask for required marking points and missing relationships. Keep unsupported additions separate. A beautiful paragraph can still omit the precise point required by the examiner.

Essay practice: outline from memory, then write a bounded response. Ask AI to compare your version with a supplied scheme rather than creating a perfect essay for you to memorise. Convert the diagnosis into a short marking checklist and reattempt with the model answer hidden. Then choose a different essay or changed sub-question testing the same concept.

Flashcards: create a small number from verified recurring factual weaknesses. One question should cue a specific retrievable answer. Preserve source/version/page and distinguish absolute statements from qualified ones. Reject cards whose answer depends on guessing the wording, hides several unrelated facts or contains an unverified correction. Use one primary spaced-repetition system for a card set.

For diagrams, use an authoritative image and verify labels, direction and relationships. Generated illustrations may simplify or misplace anatomy. Test by redrawing or labelling from memory. A memory palace is a cueing aid; explain the underlying biological relationship without the story afterwards.

Stop when the concept can be retrieved and applied. Do not build 100 cards from a topic simply because an assistant can generate them. Paper reasoning still needs papers.

Study

10 · Chemistry: derivations, mechanisms and conditions

Part I — numerical MCQs: preserve the original attempt and units. Ask the assistant to identify the first failed assumption, equation or algebraic step. Check arithmetic independently and use dimensional consistency and sensible limiting cases. A calculator validates a numerical operation, not the chemistry of the chosen equation.

Part II — calculations: write given data, requested quantity, assumptions, governing relation, substitution with units and final value. Check significant figures and whether a result is physically plausible. Keep equilibrium constants, concentration, pressure and thermodynamic quantities distinct; the question’s conditions control which relation applies.

For organic reasoning, supply the exact substrate, reagent, conditions and required transformation. Ask for a stepwise account with charge/atom balance and any uncertainty. Inspect stereochemistry and conditions against trusted course material. If the source omits conditions, the assistant must not invent them as if provided.

For qualitative analysis and equations, compare observations, reagents, ionic equations and conditions. Distinguish an observation from its interpretation. Check that atoms and charge balance. Treat generated laboratory instructions as educational material for your approved class/practical context, not a reason to experiment independently.

Use AI to construct a contrast table only after a real confusion appears: what changes, what stays constant, what assumption applies and how an examiner could distinguish the cases. Retest with a fresh question that changes one crucial condition.

If two assistants disagree, isolate the disputed step, open the resource or scheme and seek teacher clarification if still unresolved. Do not choose the answer that sounds more advanced.

Study

11 · Physics: model choice before calculation

Start with the physical system: what is included, what interacts with it, what is constant and what idealisations the question permits. Draw your own diagram. Specify signs and directions before substitution. An impressive derivation from the wrong model cannot earn the intended marks.

For mechanics or circuits, request the governing laws, assumptions and a check of your first invalid step. Verify dimensions and limiting behaviour. For graphs, identify axes, units, slope/intercept meanings and whether a fit or ideal line is justified. For experimental questions, retain measurement uncertainty and distinguish precision, accuracy and systematic error.

Image input is useful for a handwritten attempt or diagram, but ask the assistant to transcribe what it sees. Correct misread exponents, arrows and axis labels before solving. Keep your original first attempt; replacing it with the corrected answer destroys the diagnostic evidence.

After repair, solve without looking. Transfer to a new question with a changed orientation, variable, boundary condition or representation. Merely replacing names or values while copying the same worked solution is a weak transfer test.

Use the Physics Intelligence index to retrieve actual question families, then mark from the relevant trusted source. Its counts are historical navigation, not guaranteed future weighting. Log timing and uncertainty where useful, and choose the next repair from exposed mistakes rather than the most attractive heatmap.

Stop when you can explain the chosen model, reproduce the reasoning and answer an unseen related question. If that fails, repair the failed decision rather than restarting every lesson in the unit.

Integration

12 · Connect the tools without multiplying administration

One academic loop has one authoritative record. Keep the paper, scheme and source file in Drive. In the existing Notion Paper Engine, record the actual attempt, marks, marking source, assistance and next action. In the Error Bank, link a verified error to its attempt; search for duplicates first. A behavioral mistake belongs in the existing workflow/mistake system, not automatically in the academic Error Bank.

Calendar schedules intention; it must not mark work complete because a block elapsed. A timer measures elapsed time; it must not fabricate learning. A flashcard review measures that retrieval item; it does not establish essay competence. Atlas records tool learning; Powerhouse supports execution. Use links between these roles, not parallel copies of everything.

Connect an app only to complete a concrete task. Test read access with a harmless known file before any write. Confirm the correct account and file ID/title, then specify the mutation. Read the result again when verification is necessary. Check source permissions before sharing. Never make a private Drive folder public merely to fix a broken link.

The current playbook integrations are navigation and copyable workflow prompts. It does not contain an AI model endpoint, automatically pull your three accounts, sync their memories or write subscription costs to Notion. Existing authenticated site features retain their own boundaries. Tell a tool-enabled assistant to perform a supported connector action when an actual write is needed.

Cross-tool handoff: carry the precise question, your attempt, a verified source and the unresolved issue. Do not send whole private WhatsApp histories or family records to every service. Use a minimum anonymised extract only when appropriate and authorised. Before exporting a public artifact, inspect its text, file metadata, access settings and embedded links.

Verification

13 · Verify results and resolve disagreements

Treat academic marks from AI as provisional. Check against the exact authenticated scheme and appropriate source; use teacher clarification for ambiguity. Do not replace an official paper’s expected terminology with a generic internet answer. Separate factual correctness, syllabus relevance and marking eligibility.

For a generated spreadsheet, test one normal row, one blank input and one edge case; inspect formula references and recalculate. For a document, open the final file and check text, layout and links. For a site, test the changed user journey, build result and production version. For an app action, inspect the saved target. A model saying done is not independent evidence.

Keep an uncertainty register only where it affects the next action: claim, source, reason it is uncertain and who/what can resolve it. Do not store a doubtful claim as a flashcard answer. If checking consumes more time than a manual solution, choose the manual route.

Use a second model as an independent error finder, not a vote. Give it the original evidence and require an identified fault. Models can share training patterns, source errors and plausible misconceptions. If no authoritative source resolves the disagreement, say unresolved and ask a teacher.

For AI-generated transfer questions, check that the prompt is well-posed and the solution is correct before interpreting a score. Synthetic questions are practice aids; label them synthetic and never attribute them to the Department of Examinations.

A strong completion standard is an independent changed task now plus a delayed check later. Record the actual date and outcome. A scheduled retest, a checked lesson or a copied model answer is not retained mastery.

Efficiency

14 · Conserve limits, time and attention

Conserve context: use focused conversations, selected source excerpts and concise project instructions. Ask for a specific section instead of a whole-book rewrite. Supply relevant inputs together. Ask for one consolidated revision rather than many aesthetic regenerations. Keep a compact verified handoff when moving to a new topic.

Conserve expensive features: use ordinary search for a single current fact; reserve deeper research for a scoped investigation. Use media generation only for an actual learning or communication benefit. Do not spend included usage merely because it renews. Unused allowance can be a sign that you studied independently.

Official OpenAI documentation says Work and Codex share usage limits. Its pricing guidance directs you to the usage dashboard and explains that API access and additional credits can be separately charged. An existing chat’s behavior does not establish a permanent reset policy or an account-specific entitlement.

Claude’s included limits depend on context and features; inspect its displayed session/weekly reset. Gemini’s limits can change and differ by feature; use the actual account notice. Do not extrapolate an API context length or token price into a subscription’s number of tasks.

When a limit interrupts work, save a handoff, retain files and continue the independent study portion. Do not start three duplicate analyses solely to bypass waiting. If another available tool can complete a small essential action adequately, transfer only the needed input.

Give AI exploration a deliberate optional budget outside protected paper practice. Start with a short learning session, then produce actual study evidence. There is no universal safe or optimal minute quota here: adjust from your output, sleep and responsibilities. If AI browsing repeatedly consumes the intended paper block, close the tool and start the paper.

Troubleshooting

15 · Troubleshoot the actual fault

Missing feature: confirm account, plan, region, app version and the feature’s official requirements. Compare web and mobile only where available; some interfaces differ. Do not pay twice because an outdated tutorial names a control that moved.

Model misreads a file: isolate the page/section, confirm readable text, supply a clearer permitted image or paste the relevant passage. Ask it to transcribe before interpreting. If it cannot read the source, label that limitation. Do not count an inferred answer as source-grounded.

Source links fail: inspect the exact URL and permissions. Use authorised access or ask the owner for a permitted copy. Do not broaden a private file’s audience as a default repair. A link can exist without granting the recipient access.

A multi-model dashboard shows a red sign-in light but the provider works: check the real provider session and actual task result. A dashboard indicator may be stale. Record app/version, approximate time, affected provider, observed indicator and reproducible steps. Do not log out of every working account repeatedly or share cookies/tokens in a bug report.

A site seems out of date: confirm its displayed release, reload online and distinguish an offline cached page from a new deployment. Export local progress before clearing site data. Different origins maintain separate local records. If saved data is unreadable, export the damaged copy and seek recovery instead of replacing it blindly.

A connected write fails: preserve the last confirmed state and the draft. Check authorisation and target identity. Avoid retrying a send/payment/create operation until you know whether it succeeded; retries can duplicate consequential actions. For a reversible edit, verify the target and make the smallest repair.

Learning

16 · A manageable fourteen-session learning route

Use these as optional short sessions attached to real needs. They are not fourteen compulsory consecutive days. Skip a session if you can demonstrate its result independently. Delay all optional work when essentials or academic output need attention.

1. Choose one task and distinguish app, model, subscription and API. Produce one checked repair.
2. Configure one subject workspace with concise instructions. Retrieve a known passage accurately.
3. Rewrite one vague request using task, context, source, constraints, output and check.
4. Find a changing product fact in an opened official source. Record its date and applicability.
5. Use a source notebook with a small authorised collection. Open and validate one citation.
6. Compare your Biology response to a supplied scheme. Reattempt without the corrected answer.
7. Diagnose one Chemistry calculation or condition error. Pass a changed-condition question.
8. Diagnose one Physics model/sign/unit error. Pass a changed-representation question.
9. Ask another assistant for a bounded independent critique. Resolve a real disputed step from a source.
10. Create a small set of verified atomic retrieval cards from recurring weaknesses. Reject poor cards.
11. Use an available connector for one known read or authorised reversible write. Verify the resulting state.
12. Inspect an exported artifact and retain a portable backup. Explain what sync and backup do differently.
13. Calculate correction-inclusive time and cost from actual results. Identify overlap and one possible reduction.
14. Repeat a previously learned workflow on new material without step-by-step instructions. Arrange a later unaided check.

For every session, retain only a compact evidence note in the existing appropriate system: task, original attempt, assistance, verified correction, independent outcome and next retest. A self-ticked lesson is orientation progress, not certification. Do not publish anyone’s private materials as learning evidence.

Value

17 · Weekly value review and renewal decision

Start with academic outcomes: actual marked questions/essays, verified repairs, unseen transfer performance and delayed retests. Then inspect administration: one useful exported file or confirmed app action. Separate assisted output from independent performance. Review both workload and recovery.

For each plan, count accepted results you actually checked. Estimate minutes avoided versus the realistic manual or free route, then subtract prompting, setup, waiting when it displaced work, and checking/correction time. Label estimates; do not claim the tool caused an improvement simply because marks changed during the same month.

Cost per accepted result = actual monthly billed cost / verified accepted results. If there are no accepted results, show no result-based value yet; do not divide by zero. Net minutes saved = gross minutes avoided − setup/prompting/checking/correction minutes. Negative values are a signal to simplify the workflow.

Compare unique incremental benefit, not three copies of the same output. A second model’s critique can be useful; asking every model to write the same summary by default is usually redundant. Storage may have real separate value; evaluate it explicitly before a Google plan downgrade.

Choose one action: retain because essentials are covered and differentiated benefit is demonstrated; pause a low-value renewal; use free access for occasional tasks; or rotate a single paid plan around a genuine recurring need. Do not treat a trial period as permission to displace food or medication. Renew only on actual affordability and useful evidence.

End the review with one study action, not another system redesign: the next unaided question, narrow repair or overdue check. The success story is sustained learning and a more manageable life; the subscription is only one supporting resource.
